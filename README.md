# OpenCode Zen Pricing

Веб-приложение Nuxt и Python-скрипт для сравнения тарифов [OpenCode Zen](https://opencode.ai/docs/zen/#pricing) и бенчмарков [Artificial Analysis](https://artificialanalysis.ai/). Источники проверены 23 сентября 2026 года.

## Требования

- Для веб-приложения: Node.js 22.12+ и npm.
- Для отдельного скрипта: Python 3.10+; сторонние пакеты не требуются.
- Ключ Artificial Analysis необязателен. Без него доступны цены, снимок BridgeBench и ранее сохранённые бенчмарки.

## Веб-приложение

```bash
npm ci
npm run dev
```

Откройте <http://localhost:3000>.

Чтобы получать бенчмарки, создайте `.ENV` по примеру [.ENV.example](.ENV.example), если файла ещё нет, и заполните `ARTIFICIAL_ANALYSIS_API`. Существующий `.ENV` сохраняйте: в нём может быть действующий ключ.

```dotenv
ARTIFICIAL_ANALYSIS_API=your_api_key_here
```

Ключ можно получить в [Artificial Analysis](https://artificialanalysis.ai/api-reference). Поддерживаются `.ENV`, `.env` и переменные окружения; окружение имеет приоритет. Сохранена совместимость со старым написанием `ARTIFICICAL_ANALYSIS_API`. Ключ используется только на сервере.

### Сборка и production

```bash
npm run build
npm run preview
```

Для самостоятельного запуска сборки задайте ключ в окружении процесса, например через менеджер секретов или файл окружения сервиса:

```bash
export NUXT_ARTIFICIAL_ANALYSIS_API='your_api_key_here'
node .output/server/index.mjs
```

Порт по умолчанию — 3000; его можно изменить через `PORT`. Production-сервер не загружает `.ENV` автоматически. Ключ не включается в сборку: `NUXT_ARTIFICIAL_ANALYSIS_API` применяется при запуске.

```bash
npm run generate
```

Команда создаёт статический снимок в `.output/public`. Для актуализации такого сайта нужна новая генерация; работающий сервер Nuxt обновляет данные при обращении к странице/API.

## Python-скрипт

```bash
python3 opencode_pricing.py
python3 opencode_pricing.py --offline
python3 opencode_pricing.py --refresh-benchmarks
python3 opencode_pricing.py --no-benchmarks
```

Обычный запуск загружает цены и при необходимости обновляет бенчмарки. `--offline` запрещает сетевые запросы и использует локальный кэш. `--refresh-benchmarks` принудительно обновляет бенчмарки; этот флаг несовместим с `--offline`. `--no-benchmarks` отключает Artificial Analysis. При отсутствии и цен, и пригодного кэша скрипт завершится с кодом 1.

## Цены и оценки

- **Input / Output** — USD за 1 млн входных / выходных токенов, как в таблице OpenCode. Контекстные тарифы показаны отдельными строками. Строка тарифа не гарантирует доступность модели: сроки отключения перечислены в документации OpenCode.
- **Weighted** = `0.9784 × Input + 0.0216 × Output`. Это сценарий с 97.84% входа и 2.16% выхода; скидки на кэширование не учитываются. Сортировка — по возрастанию цены, при равенстве — по убыванию CodIdx.
- **Coding** — Artificial Analysis Coding Index; **GPQA** — GPQA Diamond в процентах. Нули сохраняются, отсутствующие оценки показаны как `-`.
- **CodIdx** — прежняя пользовательская шкала: `10 + 90 × max((Coding − 10.7) / (48.1 − 10.7), 0)`. Исторические опоры — Haiku 3.5 и Opus 4.6. Шкала фиксирована, не является официальной метрикой AA и может превышать 100.
- **Bridge** — Overall rating из [BridgeBench](https://www.bridgebench.ai/leaderboard). Это **ручной снимок от 2026-09-23**, общий для приложения и скрипта: [data/bridgebench.json](data/bridgebench.json). Источник теперь публикует другую шкалу; старые оценки около 90 с ней не смешиваются. Дата и ссылка отображаются рядом с результатами.

Сопоставление бенчмарков сохраняет версию и вариант модели: `Pro`, `Mini`, `Max`, `Codex` и `Spark` не взаимозаменяемы. Для одной модели среди вариантов с доступными оценками выбирается максимальный reasoning effort. Учитываются `Free`, контекстный тариф и перестановка слов в именах Claude. Исключения перечислены в [data/model_aliases.json](data/model_aliases.json). Если соответствие не подтверждено или API не публикует оценку, выводится `-`. Например, датированная версия модели не присваивается недатированному тарифу автоматически.

## Кэширование

| Данные | Python | Nuxt |
| --- | --- | --- |
| Цены | `model_pricing_cache`, обновление при каждом сетевом запуске | `.data/cache`, срок свежести 1 час |
| Artificial Analysis | `benchmark_cache.json`, срок свежести 24 часа | `.data/cache`, срок свежести 24 часа |

Кэш Python хранится рядом со скриптом; кэш Nuxt — относительно рабочей директории сервера. Для сохранения данных между перезапусками и развёртываниями обеспечьте запись и постоянное хранение `.data/cache`.

При ошибке загрузки используется последний успешный снимок с исходной датой. Устаревшие данные отмечены в выводе. Python-кэш старого формата автоматически заменяется после успешного запроса: прежний алгоритм мог сохранять оценки чужих моделей. Веб-приложение и скрипт имеют отдельные кэши. Локальные ключи и кэши исключены из Git.

## Проверки

```bash
python3 -m unittest discover -s tests -v
npm test
npm run typecheck
npm run build
```

Тесты не требуют сети или API-ключа. Общие примеры проверяют сопоставление имён в обеих реализациях; отдельные проверки покрывают изменение порядка HTML-таблиц и колонок, экранирование символов, неизвестные цены, нулевые оценки, обновление и отказ кэша, а также офлайн-запуск.
